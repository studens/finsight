# CSV·PII·LLM 파이프라인 구현 가이드

> **사용 방식:** core-services 에이전트가 이 내용을 직접 구현하지 않는다. 아래 원칙을 `phase-planning` 스킬 형식에 맞춰 Codex가 실행할 step의 작업 지시문·Acceptance Criteria로 옮겨 적는 데 사용한다.

이 파이프라인(csv-parser → pii-masking → llm)은 사용자의 원본 카드 명세서가 외부 LLM API로 넘어가기 직전의 마지막 경계다. 순서를 지키지 않거나 마스킹을 건너뛰면 개인정보가 그대로 Claude API에 전송된다.

## 파이프라인 순서는 타입으로 강제한다

세 서비스를 연결할 때, "마스킹된 데이터"와 "원본 데이터"를 같은 타입으로 다루지 않는다. 예를 들어 `MaskedRow` 타입을 만들고 `llm` 서비스의 입력 타입을 `MaskedRow[]`로만 받게 하면, 원본 `RawRow[]`를 실수로 넘기는 코드는 컴파일 시점에 걸린다. 런타임 체크(마스킹 여부 플래그)보다 타입 분리가 더 강한 방어선이다.

```typescript
// 나쁜 예: 둘 다 그냥 Record<string, string>이라 실수로 원본을 넘겨도 컴파일 통과
function analyzeWithClaude(rows: Record<string, string>[]) { ... }

// 좋은 예: 마스킹을 거쳐야만 얻을 수 있는 타입
type MaskedRow = Record<string, string> & { __masked: true };
function maskPii(rows: RawRow[]): MaskedRow[] { ... }
function analyzeWithClaude(rows: MaskedRow[]) { ... }
```

## csv-parser

- 인코딩 감지 후(EUC-KR인 국내 카드사 CSV가 흔함) UTF-8로 정규화, 메모리에서만 처리
- 헤더 + 샘플 행(컬럼 매핑 추론용, 전체 행을 Claude에 보내지 않고 일부 샘플만) 반환
- 파일을 디스크에 쓰거나 경로를 로그에 남기지 않는다 — 함수는 버퍼/스트림을 받아 파싱 결과 객체만 반환한다

## pii-masking

두 가지 처리를 구분한다:
1. **마스킹(뒤 4자리만 남김)**: 카드번호, 계좌번호 컬럼. 정규식으로 숫자/구분자를 인식해 마지막 4자리 앞을 `*`로 치환한다. 구분자(`-`, 공백) 유무 두 케이스 모두 테스트한다.
2. **컬럼 제외(마스킹이 아니라 삭제)**: 이름, 전화번호 등 신원 식별 컬럼. 이런 컬럼은 값을 변형하지 않고 컬럼 자체를 결과 객체에서 제거한다 — 마스킹 대상과 혼동하지 않는다.

컬럼 판별은 컬럼명 키워드 매칭(예: "카드번호", "계좌", "이름", "연락처", "전화") + 값 패턴(숫자 13~16자리 연속 등)을 함께 사용한다. 컬럼명이 모호하면(예: 카드사마다 헤더가 다름) 컬럼 매핑 추론 결과(아래 llm 서비스)와 연계해 판단할 수도 있지만, 매핑 확정 전에도 명백한 PII 패턴(카드번호 형식)은 항상 마스킹되어야 한다 — 매핑 추론 실패가 마스킹 누락으로 이어지면 안 된다.

TDD로 다음 케이스를 먼저 테스트한다: 구분자 있음/없음, 짧은 번호, null/빈 문자열, 여러 카드/계좌 컬럼이 동시에 있는 경우.

## llm 서비스 (Vercel AI SDK, Claude 기본값)

### 컬럼 매핑 추론
마스킹된 헤더 + 샘플 행을 Claude에 보내 date/merchant/amount/category 컬럼과 confidence를 추론한다. 프롬프트에는 "확신이 없으면 낮은 confidence를 반환하라"를 명시해, 억지로 매핑을 만들어내지 않도록 한다 — 낮은 confidence는 에러가 아니라 정상 반환값이고, 사용자 확인 UI가 처리한다.

### Free 요약 생성
카테고리별 합계, 총 지출/거래 건수, 가맹점 Top 5만 계산한다. 이건 대부분 집계 연산이라 Claude 호출 없이 코드로 계산 가능한 부분(합계, Top 5)과 Claude가 필요한 부분(카테고리 분류 자체, 컬럼 매핑에 없는 자유 텍스트 가맹점명 정규화 등)을 구분해서, 순수 계산은 굳이 LLM에 맡기지 않는다.

### Premium 리포트 생성
전월 대비/이상거래/절약 제안/예산 추천 네 종류. 각 리포트는 독립 함수로 분리해, api-routes가 `reportType` 파라미터로 하나만 골라 호출할 수 있게 한다(지연 생성이 리포트 타입 단위이므로). "전월 대비"는 직전 `analyses` 레코드를 인자로 받아 비교하는 순수 함수로 만들고, DB 조회는 이 서비스가 아니라 api-routes/db 계층 책임으로 둔다.

### 프로바이더 추상화
Vercel AI SDK의 provider 인터페이스로 감싸되, 실제로는 Claude 하나만 연결한다. 모델 선택 로직, 폴백, 여러 프로바이더 동시 지원은 만들지 않는다 — ADR-002가 명시적으로 범위 밖으로 뒀다.
