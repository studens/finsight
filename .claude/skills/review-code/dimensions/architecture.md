# 차원: 🏛 architecture (아키텍처·규약·테스트)

"동작은 하지만 이 프로젝트의 구조/규약을 어긴" 것을 찾는 차원이다. 버그 사냥은 correctness 리뷰어 몫이니 하지 마라.

## 시작 전 반드시 읽을 것

- `CLAUDE.md` (아키텍처 규칙 절)
- `AGENTS.md`
- `docs/ARCHITECTURE.md` — 디렉토리 구조 정의
- `docs/ADR.md` — 기술 선택 결정 기록

지적할 때는 이 문서들의 **해당 문장을 인용**하라. 인용할 문장이 없으면 그건 규약 위반이 아니라 당신의 취향이다 — 보고하지 마라.

## 1. 서비스 경유 규칙 (가장 자주 깨지는 것)

- 외부 API 호출(Claude, Supabase, Polar)은 **`src/services/`를 통해서만** 한다. 컴포넌트나 라우트 핸들러에서 직접 호출하면 위반.
- 추적법: `src/app/` 과 `src/components/` 안에서 SDK를 직접 import 하는 곳을 찾는다 —
  `grep -rn "@anthropic-ai\|@supabase/supabase-js\|createClient\|@polar-sh\|anthropic\|ai-sdk" src/app src/components`
- 예외적으로 허용되는 것(`src/lib/supabase/` 의 인증용 클라이언트 래퍼 등)이 있는지 ARCHITECTURE.md에서 확인한 뒤 판단하라. 무조건 지적하지 말 것.

## 2. 디렉토리 배치

| 무엇 | 어디 |
|---|---|
| 컴포넌트 | `src/components/` |
| 타입 | `src/types/` |
| Supabase 클라이언트 래퍼 | `src/lib/supabase/` |
| 외부 API 호출 로직 | `src/services/` |
| 라우트 핸들러 | `src/app/api/` |

- 새 파일이 엉뚱한 곳에 생겼는가? 타입 정의가 컴포넌트 파일에 인라인으로 흩어졌는가?
- 서비스 레이어가 UI 관심사(JSX, 포맷팅된 사용자 메시지)를 알고 있는가 — 레이어 역전.
- 라우트 핸들러가 서비스가 할 일(파싱, 변환, 프롬프트 조립)을 직접 하고 있는가.

## 3. 테스트 존재 (TDD 규칙)

`CLAUDE.md`: *"새 기능 구현 시 반드시 테스트를 먼저 작성하고, 테스트가 통과하는 구현을 작성할 것"*

- 이번에 추가된 **게이팅 로직 / PII 마스킹 / 웹훅 서명 검증 / 컬럼 매핑** 에 대응하는 Vitest 테스트가 있는가? 이 4종은 CLAUDE.md가 유닛 테스트 대상으로 못박은 것들이라 누락 시 **major 이상**.
- 테스트가 있긴 한데 해피 패스만 있는가 — 마스킹이라면 구분자 유무 두 케이스, 실패 케이스가 있어야 한다.
- 테스트가 실제 동작을 검증하는가, 아니면 목(mock)이 목을 검증하는 자기충족 테스트인가.
- 추적법: 변경된 `src/**/*.ts` 각각에 대응하는 테스트 파일이 이번 diff에 함께 있는지 대조.

## 4. 경계면 정합성 (교차 파일)

한 파일만 보면 안 보이는 것들이다. 양쪽을 **동시에 열어** 대조하라.

| 경계면 | 확인할 것 |
|---|---|
| DB 스키마 ↔ 서비스 | 컬럼명·타입·nullable 일치. 마이그레이션 없이 컬럼을 쓰고 있진 않은가 |
| 서비스 ↔ 라우트 | 함수 시그니처·인자 순서·반환 shape 일치 |
| 라우트 ↔ 프론트 | 응답 shape, 에러 코드(403/404/502) 처리 일치. 프론트가 처리 안 하는 에러 코드를 서버가 새로 반환하는가 |
| 타입 정의 ↔ 실제 데이터 | `src/types/` 의 타입이 실제 DB 행/API 응답과 어긋나는가 |

## 5. 재사용·단순화

- 이미 있는 유틸/서비스 함수를 못 찾고 새로 만들어 중복시켰는가 — Grep으로 유사 구현을 찾아 확인한 뒤에만 지적.
- 요청 범위를 넘은 추상화·설정 옵션·"나중을 위한" 확장 포인트가 들어갔는가(사용자 전역 규칙: 단순함 우선, 투기적 코드 금지).
- 이번 변경이 만든 고아 코드 — 더 이상 호출되지 않는 함수·import·타입이 남았는가. (변경과 무관한 기존 dead code는 지적 대상이 아니다. 언급만.)

## 6. 기술 스택 이탈

- ADR에 정의된 선택(Next.js App Router, Vitest, Vercel AI SDK, Supabase Auth 등)을 벗어난 라이브러리가 추가됐는가.
- `package.json`에 새 의존성이 들어왔다면 ADR에 근거가 있는지, 기존 스택으로 되는 일이 아닌지 확인.
