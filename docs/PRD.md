# PRD: finsight

## 목표
은행/카드 거래내역 CSV를 업로드하면 LLM이 분석해 지출 요약·이상거래·추이를 보여주는 개인 재무관리 SaaS.

## 사용자
- **지민 (직장인, 30대)**: 매달 카드값이 예상보다 많이 나오는데 어디서 새는지 모름 → 이상거래/중복구독 탐지에 지불 의사
- **재우 (프리랜서)**: 개인/사업 지출이 한 계좌에 섞여있음 → 정산/신고용 월별 추이 리포트에 지불 의사
- **은지 (신혼부부, 저축목표 있음)**: 여러 구독 서비스 중 안 쓰는 것을 못 찾음 → 이상거래/구독탐지에 지불 의사

## 핵심 기능
1. Google OAuth 로그인 → 대시보드 진입
2. CSV 업로드 → 파싱 → PII 마스킹 → LLM 분석 (동기 처리, 인메모리)
3. 카테고리별 지출 요약 (무료, 무제한)
4. 이상거래/구독탐지 + 월별·기간별 추이 리포트 (유료, Polar 구독)

## 검증 가설
- **H1 (PLG)**: 무료 카테고리 요약을 무제한으로 계속 쓸 수 있으면 유료 기능을 궁금해할 것이다.
- **H2 (범용 파서)**: "날짜/적요/금액" 3개 컬럼만 매핑되면 대부분의 국내 은행/카드 CSV를 처리할 수 있다.
- **H3 (온보딩 마찰)**: Google OAuth 단일 로그인만으로도 충분히 온보딩할 수 있다.
- **H4 (페이월 경계)**: "카테고리 요약"은 무료, "이상탐지/추이 리포트"가 지불 의사를 만든다.
- **H5 (신뢰)**: 금융 데이터를 다루므로 "데이터 처리 방침" 메시지가 전환율에 영향을 준다.
- **H6 (처리속도)**: 개인 CSV는 대부분 수천 행 이내라 동기 요청 하나로 처리해도 체감 대기시간이 이탈을 일으킬 정도는 아니다.
- **H7 (모델 단일화)**: Claude 단일 모델로도 3가지 리포트 품질이 충분해서, GPT 동시지원이 MVP 검증 단계의 필수 요소는 아니다.

## MVP 제외 사항
- 은행별 전용 CSV 파서 (범용 3컬럼 매핑만 지원)
- 여러 CSV 파일 동시 업로드/병합 뷰
- 모바일 앱
- 이메일/비밀번호 로그인
- 백그라운드 잡 큐 (완전 동기 처리로 대체)
- GPT 모델 선택 UI (Claude 단일 기본값)
- Polar 실제 결제 연동 (스키마/구조만, webhook·checkout은 후속 phase)
