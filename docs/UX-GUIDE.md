# UX 가이드: 유치와 단계 전환 설계

> **이 문서가 답하는 질문:** 낯선 방문자를 어떻게 "내 돈에 대해 몰랐던 걸 봤다"는 경험까지 데려가고, 그 경험이 스스로 구독을 당기게 만드는가.
>
> 시각 토큰(색·폰트·컴포넌트)은 `.claude/skills/ui-design/SKILL.md`가 관장한다. **이 문서는 "예쁘게"가 아니라 "넘어가게"를 다룬다.** 두 문서가 충돌하면 시각은 ui-design, 흐름·카피·배치는 이 문서를 따른다.
>
> 이론 뿌리: [Figma — UI Design Principles](https://www.figma.com/resource-library/ui-design-principles/). 단, 7원칙을 목차로 나열하지 않고 **각 전환 지점을 푸는 도구**로 불러 쓴다(§3).

## 1. UI의 단 하나의 임무

finsight는 세 가지 성격이 겹친 제품이다. 이 셋의 긴장을 이해하는 게 모든 UX 결정의 출발점이다.

1. **신뢰가 먼저 걸리는 관문형 제품** — 카드 명세서를 올리라고 요구한다. 신뢰가 안 서면 그 뒤 화면이 아무리 좋아도 아무도 도달하지 못한다. 신뢰는 "있으면 좋은 것"이 아니라 퍼널을 막는 **게이트**다.
2. **PLG(제품주도성장) 제품** — 무료 요약이 스스로 완결된 가치를 줘야 재방문과 입소문이 생긴다. 무료가 "맛보기 미끼"로 느껴지면 실패한다(가설 H1).
3. **기능 단위 페이월 제품** — 무료/유료 경계(H4)가 지불 의사를 만든다. 경계가 흐릿하면 아무도 결제 이유를 못 느낀다.

그래서 UI의 임무는 한 문장으로:

> **불안한 첫 방문자를, "내 돈에서 몰랐던 사실을 봤다"는 순간까지 최소 마찰로 데려간 뒤, 그 사실의 무게가 다음 단계를 당기게 한다.**

"몰랐던 사실을 본 순간" = 이 제품의 **활성화(activation) 순간**이자 아하 모먼트다. 구체적으로는 **첫 Free 요약을 눈으로 확인한 시점**. 모든 화면은 이 순간까지의 거리를 줄이거나(§2-A), 그 순간을 가로막는 불안을 없애는(§2-B) 것 중 하나를 한다. 둘 다 아닌 요소는 뺀다.

## 2. 모든 화면을 지배하는 두 힘

화면을 만들거나 고칠 때, 추가하려는 요소가 아래 둘 중 하나에 기여하지 않으면 그건 장식이다.

### A. 다음 단계까지의 거리를 줄인다 (모멘텀)
- 각 화면에는 **"지금 할 단 하나의 행동"**이 있고, 그게 시각적으로 가장 무겁다. 두 번째로 중요한 것조차 확실히 낮춘다.
- 다음 단계는 **작은 한 걸음**이어야 한다. 큰 도약(가입하자마자 결제 요구 등)은 없다. 요구를 조금씩 키우는 **커밋먼트 사다리**로 설계한다: 구경 → 로그인 → 파일 하나 → 컬럼 확인 → 결과 감상 → (그제서야) 결제 고려.
- 대기 구간에 **침묵하지 않는다.** 동기 처리라 실제 지연이 있다(H6). 몇 초라도 무엇을 하는지 말하지 않으면 사용자는 "멈췄다 = 실패"로 읽고 떠난다.

### B. 불안을 제때 없앤다 (신뢰의 적시 배치)
- 신뢰 메시지는 **광고 카피가 아니라 정보**다. "원본 CSV를 저장하지 않아요"는 반드시 뒤에 "무엇을 하는지"(마스킹된 요약만 저장, 뒤 4자리만)를 붙인다. 절반만 말하면 오히려 의심을 산다.
- 신뢰는 **한 번 말하고 끝이 아니라, 결정 직전마다 반복**한다. 랜딩에서 한 번 안심시켰어도, 실제로 파일을 올리는 버튼 옆에서 다시 안심시켜야 한다. 불안은 행동 직전에 다시 솟구치기 때문이다(H5).
- 신뢰를 **과장으로 사지 않는다.** "은행급 보안" 같은 검증 불가한 문구 대신, 우리가 실제로 하는 구체적 행동만 말한다.

이 두 힘은 자주 충돌한다(설명을 더 넣으면 신뢰는 오르지만 다음 단계까지의 거리는 멀어진다). 충돌하면 **활성화 이전 단계에서는 모멘텀을, 결제 직전에서는 신뢰를** 우선한다.

## 3. Figma 7원칙 — 언제 꺼내 쓰는가

원칙은 목적이 아니라 위 두 힘을 실현하는 연장이다. 우리 앱에서 각 원칙이 **가장 결정적인 한 곳**만 짚는다.

| 원칙 | 우리 앱에서 결정적인 지점 |
|------|------|
| **계층구조** | 결과 화면(done)에서 Free 요약 → Premium 유도 **순서**. 사용자가 "내 데이터가 잘 나왔다"를 먼저 확인한 뒤에야 업그레이드를 만난다. 순서를 뒤집지 않는다. |
| **점진적 공개** | `UploadFlow`의 `idle→confirming→done` 3단계. 한 화면에 모든 걸 주지 않는다. 매핑 확신도가 높으면 경고를 숨기고(`UploadFlow.tsx:158`), Premium 리포트는 하나씩 지연 로딩한다(`PremiumSection.tsx:189`) — 성능이 아니라 인지 부담 관리다. |
| **일관성** | 버튼/카드/배지는 `src/components/ui/*` 공용 컴포넌트만 쓴다. 화면마다 새로 스타일링하면 "매번 새로 배워야 하는" 피로가 이탈을 만든다. |
| **대비** | Free 카드와 Premium 카드가 **다른 급으로 보이게**. PREMIUM 배지·시맨틱 컬러(`border-l-4`)로 "여기부터 다른 레벨"이라는 신호(H4). 대비는 장식이 아니라 정보다. |
| **접근성** | 색만으로 Risk/Opportunity를 구분하지 않는다 — 항상 텍스트 라벨 동반. 모든 인터랙티브 요소에 `aria-label`(현 구현 유지). 4명 중 1명은 시각 제약이 있다. |
| **근접성** | 매핑 화면에서 셀렉트박스와 원본 미리보기 테이블을 붙여, "이 컬럼을 고르면 실제 어떤 값이 들어가는지" 눈으로 즉시 잇게 한다. 신뢰 문구는 업로드 버튼 **바로 위**에 둔다. |
| **정렬** | `max-w-5xl`, 좌측 정렬 기본(랜딩 히어로만 예외). ui-design 규칙과 동일하므로 재정의하지 않는다. |

## 4. 퍼널 지도와 이탈 위험

```
[랜딩 /]  ──①──▶  [로그인 /login]  ──②──▶  [빈 대시보드]
                                                  │
                                                  ③ (앱 밖: CSV를 구해 온다)
                                                  ▼
[업로드 idle] ──④──▶ [매핑 확인 confirming] ──⑤──▶ [Free 요약 done] ★활성화★
                                                          │
                                                          ⑥ Premium 잠금 카드
                                                          ▼
                                                    [구독 전환]
                                                          │
   [재방문] ◀────────── ⑦ 한 달 뒤, 두 번째 업로드 ─────────┘
       └──▶ 이력(History) ──▶ "전월 대비" 훅으로 재구독 유지
```

각 화살표의 이탈 위험과 처방을 §5에서 다룬다. **가장 과소평가되는 이탈은 ③번 — 앱 화면 어디에도 없다.** "은행 CSV를 올려주세요"형 제품의 최대 누수는, 유저가 은행 사이트에 가서 내보내기를 찾고 다운로드해 돌아오는 **앱 밖의 오프라인 단계**에서 일어난다. 여기서 대부분이 영영 안 돌아온다. 우리 UI가 이걸 직접 없앨 순 없지만, **줄일 수는 있다**(§5-③).

## 5. 전환 지점별 처방

각 항목: **사용자의 속마음 → 여기서 잃는 이유 → 설계 처방**. 처방은 실제 코드/문구에 매달아 두었다.

### ① 랜딩 → 로그인 — "이게 나한테 왜, 그리고 안전한가"
- **속마음:** "3초 안에 나한테 쓸모 있는지 판단하겠다. 그리고… 내 카드 내역을 넘기라고?"
- **잃는 이유:** 기능만 나열하면 남 얘기처럼 들린다. 신뢰가 안 서면 로그인 버튼이 무섭다.
- **처방:**
  - 히어로는 기능이 아니라 **고통**을 말한다("새는 돈이 보여요" — 유지). "AI가 분석해드립니다"류 기능 중심 카피로 바꾸지 않는다.
  - CTA는 페이지 전체에서 딱 2번(히어로·하단). 3번 이상은 절박해 보인다.
  - **신뢰를 랜딩 안에서 미리 해소한다.** "데이터를 필요한 만큼만 다뤄요" 카드(현 구현)는 로그인 결심 전에 불안을 먼저 눕히는 장치다 — 접기(fold) 아래로 밀지 말 것.
  - "세 단계면 충분해요" 섹션은 진입 장벽이 낮다는 **약속**이다. 실제 플로우(업로드→매핑확인→인사이트)와 문구가 어긋나면 첫 사용에서 신뢰가 깨진다. 플로우를 바꾸면 이 카피도 같이 고친다.

### ② 로그인 — 마찰 제로 구간
- **속마음:** "빨리 넘어가자."
- **잃는 이유:** 여기서 선택지를 늘리거나 설명을 붙이면 오히려 의심과 피로가 생긴다.
- **처방:** 카드 하나·문구 한 줄·버튼 하나(현 구현) 유지. Google 단일 로그인(H3)이 정답이다. **실험적 UI를 넣을 곳이 아니다.**

### ③ 로그인 → 첫 업로드 — 앱 밖의 절벽 (최대 누수)
- **속마음:** "로그인은 했는데… CSV? 그걸 어디서 받지?" → 탭을 닫는다.
- **잃는 이유:** CSV를 구하는 건 앱 밖의 여러 단계(은행 로그인 → 내보내기 메뉴 찾기 → 기간 선택 → 다운로드)다. 이 마찰이 침묵의 최대 이탈원이다.
- **처방:**
  - 빈 대시보드를 **막막한 빈 화면으로 두지 않는다.** 첫 방문자에게는 업로드 카드 자체가 온보딩이어야 한다.
  - "어떤 CSV든 괜찮다"는 확신을 준다(H2 자동 매핑) — 유저가 "우리 은행 형식도 되나?"로 주저하지 않도록. 현 업로드 문구가 이 역할을 하니 유지·강화한다.
  - **CSV를 어디서 받는지 짧은 힌트**를 업로드 화면 안에 둘 가치가 크다(예: "카드사/은행 앱 → 이용내역 → 내보내기(CSV)"). 앱 밖 단계를 앱 안에서 안내하는 이 한 줄이 ③ 이탈을 실질적으로 줄인다. — *현재 미구현, 우선 개선 후보.*
  - 샘플 CSV로 **빈손으로도 결과를 먼저 맛보게** 하는 것도 강력하다(가치를 먼저 증명 → CSV 구해올 동기 부여). *MVP 범위 확인 필요, 검토 후보.*

### ④ 업로드(idle) → 매핑 — 첫 행동과 첫 대기
- **속마음:** "올렸다. …되고 있나?"
- **잃는 이유:** 업로드 후 몇 초의 침묵을 실패로 오인.
- **처방:** "파일을 확인하고 있어요..." 진행 문구(현 구현) 반드시 유지(H6). 드롭 영역 강조(`outline`)로 드래그가 먹혔음을 즉시 피드백.

### ⑤ 매핑 확인(confirming) → 분석 — 퍼널에서 가장 위험한 인지 부하 지점
- **속마음:** "왜 나한테 컬럼을 고르라는 거지? 틀리면 어쩌지?"
- **잃는 이유:** 이유 설명 없이 셀렉트박스만 던지면 "이거 어려운 도구구나" 하고 이탈. 매번 강한 경고를 띄우면 피로로 이탈.
- **처방:**
  - **왜 확인하는지 한 줄**을 항상 곁에 둔다("분석에 사용할 컬럼이 맞는지 확인해 주세요" — 유지).
  - 경고는 **확신도 낮을 때만**(`confidence < 0.7`) 노출(현 구현 유지). 항상 띄우면 "매번 검사받는" 피로가 된다 — 점진적 공개 원칙.
  - 셀렉트박스 ↔ 원본 미리보기 테이블을 **붙여** 선택 결과를 즉시 눈으로 잇게 한다(근접성).
  - 필수 컬럼(날짜·가맹점·금액) 전엔 "분석 시작" **버튼 비활성화**로 사전 방지(현 구현). 에러 모달로 사후 통보하는 것보다 마찰이 적다.
  - PII 처리 결과(`제외된 컬럼`·`뒤 4자리만`) 안내를 분석 버튼 **바로 위**에 둔다(신뢰의 적시 배치, §2-B).

### ⑥ Free 요약(done) — ★활성화★, 이 앱에서 가장 중요한 화면
- **속마음:** "오, 이게 내 돈이구나." (또는 "그래서 뭐?")
- **잃는 이유:** 결과가 그냥 표로 보이면 "아하"가 없다. 아하가 없으면 재방문도, 결제 고려도 없다.
- **처방:**
  - `FreeSummaryCards`를 **화면 최상단**에 즉시. 숫자(총 지출·Top 5 가맹점)는 `font-mono tabular-nums`로 무게를 준다.
  - 여기서 **결제를 강하게 밀지 않는다.** Free 결과 자체의 완성도로 재방문을 만들고(H1), Premium은 그 아래에서 자연스럽게 흐르게 한다(계층구조).
  - 가능하면 요약을 **발견형으로** 쓴다: 단순 합계보다 "구독에 매달 X원, 지난 분석보다 늘었어요"처럼 유저가 몰랐을 사실을 앞세울수록 활성화가 강해진다. *데이터가 허락하는 선에서 카피 발전 후보.*

### ⑦ Premium 잠금 카드 → 구독 — 돈이 걸린, 가장 섬세한 순간
별도 절(§6)에서 상세히.

### 재방문 & 리텐션 — History가 훅이다
- **긴장:** "전월 대비" 리포트는 구조상 **두 번의 업로드(두 달)**가 있어야 의미가 생긴다 → 첫 방문과 두 번째 방문 사이 한 달의 공백. 이 공백을 어떻게 넘길 것인가가 리텐션의 핵심.
- **처방:**
  - 이력(`HistoryList`)은 단순 로그가 아니라 "전월 대비"의 **존재 이유(비교 기준)**를 쌓는 장치. 이력이 늘수록 Premium "전월 대비 증감"의 실제 가치가 커진다.
  - 두 번째 분석부터 "이제 전월 대비 리포트가 의미 있어요" 같은 상기 문구가 재구독을 자연스럽게 당길 수 있다. *과욕 금지 — 지금은 방향만, 구현은 신중히.*
  - 한 달 공백을 메우는 재방문 유도(이메일·알림)는 **MVP 범위 밖**(`docs/PRD.md` 제외 목록). 지금은 진입점을 대시보드 하나로 유지하고, 이 공백이 알려진 리스크임을 기록해 둔다.

## 6. 페이월: 강요 없이 궁금하게

돈이 걸린 유일한 순간이라 별도로 다룬다. 원리는 **"열린 고리(open loop)"** — 사람은 시작됐지만 안 끝난 것을 견디기 어렵다. 단, 그 고리가 **정직**해야 신뢰(§1의 게이트)가 깨지지 않는다.

- **가짜로 흐리지 않는다.** Free 사용자에겐 Premium을 애초에 서버가 생성하지 않으므로(지연 생성) 보여줄 값이 없다. `backdrop-filter: blur()`로 가짜 데이터를 흐리게 깔지 않는다(ui-design 규칙과 동일). **빈 상태 + 리포트 이름 + 한 줄 설명 + CTA**로만 구성한다.
- **설명은 추상적 혜택이 아니라 구체적 질문으로.** "더 똑똑한 분석"이 아니라 "이번 달, 카테고리별로 얼마나 늘었을까요?"처럼 방금 올린 그 데이터를 가리키는 톤일수록 고리가 강하게 열린다. (현 문구 "전월 대비 지출 변화를 확인하세요"는 이 방향의 좋은 출발점.)
- **CTA는 "결제"가 아니라 "보기".** "Premium으로 보기"(현 문구 유지). 결제 행위보다 "보는 것"을 약속하는 톤이 마찰이 낮다.
- **경계는 선명하게, 압박은 낮게.** PREMIUM 배지·급 차이(대비 원칙)로 "여기부터 다른 레벨"은 분명히 하되, "지금 안 하면 손해"식 공포 카피는 쓰지 않는다.
- **(연동 상태 주의)** 이번 phase는 Polar 체크아웃 전이라 CTA가 실제 결제로 이어지지 않는다. `polar-billing` phase에서 연동할 때 **문구·위치는 그대로 두고 `onClick` 핸들러만 채운다** — 여기서 검증한 톤을 깨지 않기 위해서다.

## 7. 카피 톤 원칙
- **과장 금지.** "혁신적 AI" 같은 상투어 대신 숫자·사실로 말한다("무료·무제한", "뒤 4자리만").
- **손실은 자극하되 공포로는 안 간다.** "새는 돈"까지 허용, "지금 안 하면 손해"류 압박은 금지.
- **신뢰 문구는 정보로.** "저장하지 않아요" 뒤엔 항상 "무엇을 하는지"를 한 문장으로 붙인다.
- **명령이 아니라 안내.** "업로드하세요"보다 "올리면 바로 보여드려요"처럼 결과를 약속하는 톤.
