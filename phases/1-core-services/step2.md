# Step 2: pii-masking 서비스 — 카드/계좌 마스킹 + PII 컬럼 제외

## 작업
`src/services/pii-masking/`에 PII 처리 서비스를 TDD로 구현한다. **테스트를 먼저 작성**하고 통과하는 구현을 작성한다. 이 서비스는 원본 CSV가 외부 LLM으로 넘어가기 직전의 마지막 경계이므로, 마스킹 누락은 곧 개인정보 유출이다.

공개 함수(정확한 시그니처):
```typescript
// src/services/pii-masking/index.ts
export function maskPii(parsed: ParsedCsv): MaskedDataset;
```
- 입력은 step 1 csv-parser가 반환한 `ParsedCsv`(원본 `RawRow[]`).
- 반환은 step 0의 `MaskedDataset = { headers: string[]; rows: MaskedRow[]; excludedColumns: string[]; maskedColumns: string[] }`.
- **`MaskedRow` 브랜드는 오직 이 함수만 부여한다** — 마스킹/컬럼제외 처리를 마친 뒤에만 브랜드를 붙인다.

두 가지 처리를 **명확히 구분**한다:
1. **마스킹(뒤 4자리만 남김)** — 카드번호/계좌번호 컬럼. 값의 숫자를 인식해 마지막 4자리를 제외한 앞부분을 `*`로 치환한다. 구분자(`-`, 공백) 유무 모두 처리한다.
2. **컬럼 제외(값 변형이 아니라 컬럼 자체 삭제)** — 이름/전화번호/연락처 등 신원 식별 컬럼. 이런 컬럼은 결과 `rows`의 각 객체와 `headers`에서 **키 자체를 제거**한다. 절대 마스킹 처리(값 변형)로 대체하지 않는다.

컬럼 판별: 컬럼명 키워드 매칭(예: "카드번호","카드","계좌","account","card" → 마스킹 / "이름","성명","name","전화","연락처","휴대폰","phone","tel" → 제외) + 값 패턴(연속 숫자 13~16자리 → 카드/계좌로 간주 마스킹)을 함께 사용한다. **컬럼명이 모호해도 명백한 카드번호 형식(숫자 13~16자리, 구분자 포함 형태)은 항상 마스킹된다** — 컬럼명 매칭 실패가 마스킹 누락으로 이어지면 안 된다.

## Acceptance Criteria
- [ ] (구분자 두 케이스) 카드번호 `1234-5678-9012-3456`와 `1234567890123456` **두 케이스 모두** 뒤 4자리(`3456`)만 남고 앞자리가 `*`로 마스킹되는 Vitest 테스트가 통과한다.
- [ ] 계좌번호(구분자 있음/없음 포함)도 뒤 4자리만 남기고 마스킹되는 테스트가 통과한다.
- [ ] (마스킹 vs 제외 구분) 이름/전화번호 컬럼이 값 마스킹이 **아니라** 결과 객체에서 **키(컬럼) 자체가 제거**되는지 별도 테스트로 확인한다: 마스킹 후 `rows[i]`에 해당 키가 존재하지 않고(`'이름' in row === false`), `headers`에도 없으며, `excludedColumns`에 해당 컬럼명이 담긴다.
- [ ] 엣지 케이스 테스트 통과: 짧은 번호(4자리 이하 — 마스킹할 앞자리가 없으면 원본 유지 또는 전체 마스킹 규칙을 정해 테스트로 고정), `null`/빈 문자열 셀, **카드·계좌 컬럼이 동시에 여러 개** 있는 CSV에서 모든 해당 컬럼이 마스킹된다.
- [ ] (컬럼명 모호 대비) 컬럼명이 매칭 키워드에 없어도 값이 명백한 카드번호 형식(숫자 13~16자리)이면 마스킹되는 테스트가 통과한다.
- [ ] (타입 경계) `maskPii`의 반환 `rows`만 `MaskedRow[]`이고, 입력 `RawRow[]`를 그대로 `MaskedRow[]`로 통과시키는 경로가 없다. 브랜드는 이 함수 내부에서만 부여됨을 코드로 확인한다.
- [ ] (원본 미보관 CRITICAL) 이 서비스 코드에 원본/마스킹 전 행을 디스크에 쓰거나 로그로 남기는 호출이 없음을 grep으로 확인한다.
